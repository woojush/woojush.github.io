# 04. Design System

> 상태: v0.2 — 승인됨, 최종 결정 반영 (2026-10-04) · 최초 작성 2026-10-04
> 색상·서체는 **제안값**이다. 구현 후 실제 화면을 보고 조정할 수 있도록 모두 토큰(CSS 변수)으로 관리한다.

## 1. 디자인 원칙

> **2026-10-10 개정:** 방향이 바뀌었다. 움직임·메인 히어로·색(어두운 기본)은 `docs/07_design_direction.md`가 우선한다. 아래 표 중 "움직임은 사용자 동작에 반응할 때만", "히어로 + CTA 금지", "첫 화면은 이름과 한두 문장", "섹션 등장 효과 금지"는 07의 허용 범위(메인 한정 등장, 페이지 전환)만큼 완화된다. CTA 버튼·아이콘 3열·통계 블록·카드 그리드 금지와 eyebrow 라벨 금지는 그대로다.

브리프 12번을 시각 규칙으로 번역한다.

| 브리프의 표현 | 이 사이트에서의 구체적 규칙 |
|--------------|---------------------------|
| Minimal / No unnecessary decoration | 그림자, 그라디언트, 둥근 카드 배경, 장식 아이콘을 쓰지 않는다. 구분은 **여백과 얇은 선(1px)** 으로만 한다 |
| Typography-driven | 위계는 **크기·굵기·여백**으로 만든다. 색으로 위계를 만들지 않는다 |
| Editorial / Calm | 본문 한 줄 길이를 제한하고, 줄 간격을 넉넉하게. 움직임은 사용자 동작에 반응할 때만 |
| No excessive cards | 목록은 카드가 아니라 **행(row)**: `날짜 | 제목 | 상태`. 카드 그리드를 쓰지 않는다 |
| No generic SaaS aesthetic | 히어로 + CTA 버튼, 아이콘 3열 소개, 숫자 통계 블록을 쓰지 않는다 |
| Personal | 첫 화면은 이름과 한두 문장. 그다음에 NOW |

**피하는 흔한 패턴** (생성형 디자인에서 자주 나타나는 "기본값"이라 의도적으로 제외):

- 모든 제목 위에 영문 대문자 + 자간 넓은 소제목(eyebrow) 라벨
- 링크/버튼 끝에 `→`를 붙이는 것
- 메타 정보를 `A · B · C`처럼 가운뎃점으로 나열한 문자열을 모든 곳에 쓰는 것
- 크림색 배경 + 테라코타 포인트, 또는 검정 배경 + 형광 포인트 조합
- 모든 요소에 같은 border-radius
- 섹션마다 아래에서 위로 올라오며 나타나는 등장 효과
- 번호 마커(01 / 02 / 03)를 순서가 없는 내용에 붙이는 것 (순서가 *있는* Timeline의 연도 표기는 정당한 사용)

## 2. 색상 토큰

중립적인 차가운 회색 계열 + 어두운 청록색 포인트 하나. 포인트 색은 **링크, 포커스 링, 선택 영역**에만 쓴다.

| 토큰 | Light | Dark | 용도 |
|------|-------|------|------|
| `--bg` | `#FBFBFA` | `#14161A` | 페이지 배경 |
| `--text` | `#1B1D21` | `#E6E7E9` | 본문 |
| `--text-muted` | `#6A6F78` | `#959AA3` | 날짜, 메타, 보조 설명 |
| `--rule` | `#E3E4E6` | `#2A2D33` | 1px 구분선 |
| `--accent` | `#2F5D62` | `#7FB5B0` | 링크, 포커스, 선택 |
| `--code-bg` | `#F2F3F4` | `#1C1F24` | 코드 블록 / 인라인 코드 배경 |

접근성 점검 (대략적 계산값, 구현 시 도구로 재확인):

- 본문 `--text` / `--bg`: 대비 약 15:1 (기준 4.5:1 이상)
- `--text-muted` / `--bg`: 라이트 약 4.8:1, 다크 약 6:1 → 작은 글씨에도 사용 가능하나 **더 연하게 만들지 않는다**
- `--accent` / `--bg`: 라이트 약 7:1, 다크 약 8:1

**상태(status) 표현**: 색으로 구분하지 않는다. `seed / growing / evergreen`은 **텍스트(작은 글씨, muted)** 로 표시한다. 색맹 사용자와 흑백 인쇄 모두에서 같은 정보가 전달되고, 색상이 늘어나 화면이 시끄러워지는 것도 막는다.

**테마 동작**:

- 3상태: `system`(기본) / `light` / `dark`. 헤더의 토글 하나로 순환.
- 선택은 `localStorage`에 저장. **페이지가 그려지기 전에** `<head>`의 아주 작은 인라인 스크립트로 `data-theme`를 지정해서, 다크 모드 사용자가 흰 화면이 번쩍이는 것을 보지 않게 한다.
- 수식(KaTeX)과 코드 블록, Mermaid도 같은 토큰을 따른다 (코드: Shiki 듀얼 테마, Mermaid: 테마 변경 시 재렌더).

## 3. 타이포그래피

한국어와 영어가 섞인 긴 글이 주 콘텐츠이므로 한글 가독성이 우선이다.

| 역할 | 서체 | 이유 |
|------|------|------|
| 본문 / UI / 제목 | **Pretendard Variable** (self-host, 동적 서브셋) | 한글과 라틴 문자가 한 서체 안에서 균형이 맞음. 가변 폰트라서 굵기 조정이 자유롭고, 서브셋 덕분에 글리프가 많은 한글 폰트의 용량을 줄일 수 있음 |
| 코드 | **JetBrains Mono** (self-host) 또는 시스템 monospace | **코드에만** 사용. 날짜/라벨 같은 메타 정보에는 쓰지 않음 |
| 수식 | KaTeX 내장 서체 | 수식 엔진이 번들 |

- 서체를 한 가족으로 쓰는 대신 **굵기와 크기의 대비**로 위계를 만든다.
- 외부 CDN 대신 self-host: 로딩 안정성, 개인정보, 오프라인 빌드 재현성.
- (결정 사항) 긴 Knowledge 본문에 serif 본문 서체를 쓸지. 한글 serif는 파일이 크고 라틴 서체와 짝맞춤이 필요해서, 기본은 sans 한 가족으로 시작한다.

### 크기 스케일 (기본 17px, 비율 약 1.2)

| 토큰 | 크기 | 줄 간격 | 용도 |
|------|------|---------|------|
| `--fs-s` | 14px | 1.5 | 날짜, 메타, 캡션 |
| `--fs-base` | 17px | **1.75** | 본문 (한글은 줄 간격이 넉넉해야 읽기 편함) |
| `--fs-m` | 20px | 1.5 | 목록 제목, 리드 문장 |
| `--fs-l` | 25px | 1.35 | H3 |
| `--fs-xl` | 31px | 1.3 | H2 |
| `--fs-2xl` | 40px | 1.2 | 페이지 제목 (H1) |

### 본문 폭 (measure)

- 글 본문 최대폭 **약 680px** → 한글 약 40자 / 영문 약 70자. (한 줄 80자 미만)
- 정렬: **왼쪽 정렬**. justify와 가운데 정렬은 쓰지 않는다.
- 코드 블록·표·Embed는 본문보다 넓어질 수 있으며(최대 약 880px), 화면이 좁으면 **그 요소 안에서** 가로 스크롤한다. 페이지 전체가 옆으로 밀리지 않는다.

## 4. 간격과 레이아웃

- 간격 단위: 4px 기반. `4 / 8 / 12 / 16 / 24 / 32 / 48 / 72 / 112`.
- 섹션 사이 간격은 **72~112px**로 넉넉하게. 구분선은 섹션 경계에만 사용하고 모든 곳에 넣지 않는다.
- 페이지 구조:

```
┌───────────────────────────────────────────────┐
│ header: 이름(좌)      nav 4~5개 + 테마토글(우)    │  높이 약 64px, 스크롤 시 고정하지 않음 (MVP)
├───────────────────────────────────────────────┤
│                                               │
│        본문 컬럼 (max 680px, 왼쪽 정렬)           │
│                                  ┌──────────┐ │
│                                  │ TOC      │ │  글 페이지 + 화면 ≥ 1100px에서만
│                                  │ (sticky) │ │  그 미만에서는 본문 상단에 접이식
│                                  └──────────┘ │
├───────────────────────────────────────────────┤
│ footer: 링크 몇 개, 저작권                       │
└───────────────────────────────────────────────┘
```

- 반응형 기준: 모바일(~640px) · 태블릿 · 데스크톱(1100px~). 모바일 메뉴는 **5개 링크가 한 줄에 안 들어갈 때만** 접는다 (5개는 대부분 그대로 들어가므로 햄버거 메뉴를 기본으로 두지 않는다. 화면 폭이 모자랄 때 줄바꿈 또는 간단한 토글).

## 5. 컴포넌트 시각 규칙

| 컴포넌트 | 규칙 |
|----------|------|
| **목록 행 (EntryRow)** | `[날짜(muted, 고정폭 열)] [제목] [상태/kind(muted, 우측)]`. hover 시 제목에 밑줄. 배경색 변화 없음. 모바일에서는 날짜가 제목 위로 올라가 두 줄 |
| **NOW 블록** | 정의 목록 형태. 왼쪽 열 = 라벨(muted, 고정폭 약 96px), 오른쪽 = 내용(본문 크기). 박스/배경 없음, 위쪽에 얇은 선만 |
| **링크** | 본문 안의 링크는 `--accent` + 밑줄(얇게). 목록/메뉴의 링크는 밑줄 없이 `--text`, hover에서 밑줄 |
| **현재 메뉴 표시** | 현재 페이지 메뉴는 굵기(weight)를 올리고 `aria-current="page"`. 색만으로 표시하지 않음 |
| **태그** | `#linear-algebra` 형태의 muted 텍스트. 칩/배경 없음 |
| **TOC** | 본문 옆 작은 글씨, 현재 읽는 섹션을 굵게. 접근성을 위해 `nav` 랜드마크 |
| **코드 블록** | `--code-bg` 배경, 1px `--rule` 테두리, radius 4px. 언어 라벨은 우상단에 작게. 줄 번호는 기본 끔 |
| **수식 블록** | 가운데 정렬 대신 **왼쪽 들여쓰기**. 긴 수식은 블록 안에서 가로 스크롤 |
| **Callout** | 왼쪽 2px 선 + 약간의 들여쓰기. 아이콘/배경색 없음. 종류: note, warning 정도만 |
| **Embed (인터랙티브)** | 1px `--rule` 테두리의 프레임 + 아래에 캡션(muted). 로딩 전에 높이를 확보해서 레이아웃이 밀리지 않게 함 |
| **표** | 가로선만. 세로선과 지브라 스트라이프 없음. 좁은 화면에서는 표 안에서 가로 스크롤 |
| **Related (관계)** | 제목 없는 얇은 선 아래에 `관계명 / 대상 제목`의 두 열. 종류(type)를 괄호로 표시 |
| **Timeline** | 왼쪽 열 = 기간(연도), 오른쪽 = 제목과 항목. 세로선 한 줄로 연결하되 점/아이콘 장식 없음 |

## 6. 인터랙션과 모션

> **2026-10-10 개정:** 아래 표에서 "이동/크기 애니메이션 없음", "페이지 진입 효과 없음"은 `docs/07` §3(탭 표시 이동·페이지 전환·메인 한정 등장)으로 대체된다. reduced-motion에서 전부 끈다는 규칙은 그대로다.

| 항목 | 규칙 |
|------|------|
| 전환(transition) | 색상·밑줄·투명도만, **120~160ms**. 이동/크기 애니메이션 없음 |
| 페이지 진입 효과 | 없음 |
| `prefers-reduced-motion` | 모든 전환을 비활성화 |
| 포커스 | **항상 보이는** 포커스 링: `outline: 2px solid var(--accent); outline-offset: 2px`. 마우스 클릭에는 `:focus-visible`로 숨김 |
| 키보드 | 페이지 맨 앞에 "본문으로 건너뛰기" 링크. 논리적 Tab 순서. (단축키 `j/k`, `/` 등은 MVP에서 제외) |
| 이미지 확대 | MVP 제외 |
| 스크롤 | 앵커 이동 시 고정 헤더가 없으므로 `scroll-margin`만 약간. `scroll-behavior: smooth`는 reduced-motion이 아닐 때만 |

## 7. 접근성 기준 (품질 하한선)

- 본문 대비 4.5:1 이상, 큰 글씨 3:1 이상
- 모든 이미지에 `alt` (장식용은 빈 alt). 스키마에서 `cover`에 `alt`를 함께 요구하는 방안은 구현 시 결정
- 시맨틱 랜드마크: `header`, `nav`, `main`, `footer`, 글 `article`
- 제목 위계(h1→h2→h3)를 건너뛰지 않음. 페이지당 h1은 하나
- 색상만으로 정보를 전달하지 않음
- 모바일 터치 영역 최소 44px

## 8. 사이트 문구(copy) 원칙

- UI 문구는 짧고 구체적으로. 설명보다 이름: `Recent writing`, `Selected projects`.
- 빈 상태는 **숨긴다**. "아직 글이 없어요" 같은 안내 문구를 만들지 않는다.
- 문장형 대소문자 (Sentence case). 메뉴 항목도 소문자 `about`, `knowledge`, `projects`, `writing`으로 표시한다 (브리프의 대문자는 정보 구조의 이름이지 화면 표기가 아님 → 결정 사항).
- 같은 동작에는 같은 단어를 쓴다 (예: 항상 `updated`, 때로는 `modified`로 바꾸지 않음).

## 9. 디자인 토큰 파일 구조 (구현 시)

```text
src/styles/
  tokens.css   ← 색상·서체·간격·크기 토큰(CSS 변수)만. 이 파일만 고치면 사이트 전체의 룩이 바뀜
  base.css     ← reset, body, 링크, 포커스
  prose.css    ← 글 본문(마크다운 렌더 결과)의 타이포그래피
```

컴포넌트는 색·크기를 직접 쓰지 않고 항상 토큰을 참조한다. 이렇게 하면 "포인트 색을 바꾼다", "본문 크기를 18px로 한다" 같은 수정이 **한 파일의 한 줄**로 끝난다.
