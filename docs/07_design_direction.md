# 07. Design Direction (v2)

2026-10-10. 원래 브리프(차분·미니멀·에디토리얼)를 대체하는 새 방향이다.
`docs/04`와 충돌하는 부분은 이 문서가 우선하며, 04의 해당 항목에 같은 내용을 반영했다.

## 1. 왜 바꿨나

Phase 1의 결과가 "정적이고 AI 느낌"이라는 피드백. 원인은 (1) 안전한 회색+청록 팔레트, (2) 비어 있는 메인,
(3) 움직임을 거의 금지한 규칙이다. 목표는 "적당히 동적이고 감각적이며, 메인은 창의적·신박한 첫인상".
이 사이트는 취업용이 아니라 느낀 것을 쌓다 보면 포트폴리오가 되는 아카이브다.

## 3. 움직임 규칙 (허용 범위)

- **a. 마이크로 인터랙션:** 링크·탭·토글의 색/밑줄 전환 140ms.
- **b. 페이지 전환:** 사이트 안 이동 시 CSS View Transitions. 헤더는 고정, 탭 표시가 이전 탭에서 새 탭으로 미끄러지고(600ms), 본문은 크로스페이드. 미지원 브라우저는 평소대로 이동.
- **메인 한정:** 배경 별(먼지) 입자 장면(three.js, 포인터 시차, `src/scripts/scene.ts`)과 첫 문구의 점진 확대·홈 화면 공개(아래 "메인 인트로"). 로드당 한 번.
- **c. 탭 바 (2026-10-10 사용자 지시·승인, 위 a·b의 범위를 넘는 예외):** lifestories.org의 상단 알약을 **CSS 값까지 그대로** 따른다(사이트의 `s-header__action*` 규칙을 복사). 데스크톱(마우스)에서는 화면 위 가운데에 떠 있는(fixed) 작은 알약(260px)이고 가운데에 점 4개 허브가 있다. 마우스가 올라가면 스프링(cubic-bezier .44,1.85,.6,1, 600ms)으로 늘어나고(416px, 원본은 360px인데 한글 라벨 때문에 넓힘) 글자가 바깥에서 안쪽으로 모이며 나타난다. 알약 면은 약간 그레이의 반투명 배경(어두운 테마 rgba(140,140,140,.22), 밝은 테마 rgba(110,110,110,.16), 원본과 다름) + 뒤 화면 블러 15px이고, 안쪽 가장자리에서 tan·orange·green·red 4색 빛이 12·9·5초 주기로 원본보다 2.5배 크게 움직이되 은은하게(투명도 .6) 떠돌며(호버하면 더 크게 움직이고 밝아짐), 테두리를 8초에 한 바퀴 도는 검은 빛줄기가 있다. 글자에 마우스를 올리면 하얀 빛(hover-blob, 투명도 .5로 은은하게)이 알약 안쪽 아래에서 올라와 그 글자 밑을 따라 움직인다(알약 밖으로 나가지 않게 안쪽에 둠 — 원본과 다른 유일한 점). 허브는 올라갈 때 90° 돈다. 모바일·터치는 이름 아래 한 줄에 글자가 처음부터 보이는 알약이다. 값은 `tokens.css`의 탭 바 토큰, 모양은 `src/styles/nav.css`. 이 효과는 탭 바에만 쓰며 다른 곳으로 넓히지 않는다.
- **메인 한정 추가 (2026-10-11 사용자 지시):** 인트로가 끝날 때 블랙홀의 **어둠이 가운데에서 번져** 화면을 덮고 그 어둠 위로 흰 요약정리가 나타나며, 홈에서 Knowledge로 갈 때는 **흰 빛이 도착한 Knowledge에서 걷히며 별 세계가 드러난다**(아래 "흰 세계"). 이 둘만 홈 한정 예외다.
- **금지 유지:** 스크롤할 때마다 요소가 올라오는 효과, 장식 그림자·그라디언트, 자동 슬라이드. (메인 인트로가 끝나면 홈 화면이 저절로 나타나는 것은 사용자 지시(2026-10-10)에 따른 메인 한정 예외다. 다른 페이지로 이동시키지는 않는다.)
- `prefers-reduced-motion: reduce`이면 위 움직임을 전부 끈다 (문구는 처음부터 보이고, 장면은 정지 화면, 페이지 전환 없음).

## 4. 색·서체

- **어두운 세계가 기본이다.** 사용자가 테마를 고르는 기능은 없다(2026-10-11 토글·라이트 테마 삭제). 단 하나의 예외인 **흰 세계**는 홈의 요약정리와 projects(목록·상세)만 흰 바탕이다(2026-10-11 사용자 지시, 아래 "흰 세계"). about·writing·knowledge는 어두운 바탕 그대로다.
- 어두운 바탕은 약간 따뜻한 먹색(#121211), 글자는 따뜻한 흰색(#ebe7df), 포인트는 앰버(#e0a96d). 원래 브리프의 "목재·자연" 쪽으로 맞춘 것이다.
- 포인트 색은 링크·포커스·선택에만 쓴다. 탭의 현재 위치는 색이 아니라 표시 면(`--surface`)과 굵기로.
- 서체는 Pretendard 한 가족을 유지한다. 메인 큰 문구는 `--fs-display`(32~64px).

## 5. 구성

- **상단 탭 바:** 메뉴 4개(projects/about/knowledge/writing, 2026-10-10, home은 메뉴에서 제외)를 §3 c의 알약으로 표시. 각각 별도 URL의 일반 링크(ARIA tabs 아님). 홈은 이름(헤더 왼쪽)과 알약 가운데 허브가 링크한다. 사용자가 향후 직접 수정할 수 있으며 순서와 이름은 유지한다.
- **메인(`/`):** 첫 방문에는 인트로(별 입자 장면 + 점점 커지는 큰 문구), 끝나면 홈 화면(프로필·Now·Projects·Recent). 아래 "메인 인트로 → 홈 화면".
- **읽는 페이지(knowledge, writing, about):** 조용하게 유지. 별 장면 등 메인 전용 효과 없음.

## 메인 별 장면 (2026-10-10 사용자 승인)

lifestories.org/discover의 별(먼지) 장면을 기준으로 하되 코드는 복사하지 않고 원리만 보고 직접 구현했다. **three.js(0.170)를 의존성으로 추가**했다(사용자 승인). 카드·사진은 쓰지 않는다. 코드: `src/scripts/scene.ts`, 문구·비네팅: `HomeHero.astro`.
- **별:** 약 3천 개(모바일 1.5천)가 처음부터 이미 자리에 있고, 원근법대로 멀리서는 중앙에 모여 있다가 점차 앞으로 다가오며 가속해 테두리 쪽으로 퍼져 나간다(끝없는 비행). 뭉침(성단)은 거의 없이 고르게 흩어져 있다(등고선처럼 보이지 않게). 입자마다 제 박자로 반짝이고, 크기는 처음(먼 곳) 크기에서 시작해 다가올수록 원근법대로 점점 커진다. 한가운데에도 별이 있되, 별이 생겨나는 위치를 소실점에서 조금 떨어뜨리고 가장 안쪽만 옅게 해 '시작점'이 생기지 않게 한다. 별의 최소 크기는 3px(discover는 1px인데 사용자 요청으로 2px 키움)이다. 비행 속도는 문구가 커지는 속도에 맞춰 정해진다(아래 "메인 인트로").
- **테두리 효과:** 줄무늬·색수차는 쓰지 않는다(사용자 요청으로 제거). 가장자리 별은 옅게 보이고, 비네팅(40%에서 시작, 배경색 80%)과 얇은 그레인으로 시선이 가운데로 모인다.
- **문구:** 화면 정중앙, 가운데 정렬. 별이 2초 먼저 보인 뒤 메인 문장(25px)이 한 번에 나타나 천천히 커지고, 3.8초에 아래에 작은 문장(17px, 메인보다 8px 작음)이 나타나 같이 커진다. 움직임을 줄이는 설정이면 처음부터 보이고 움직이지 않는다.
- 메인에만 쓰고 WebGL이 없으면 별만 숨긴다(문구의 확대와 화면 전환은 그대로 동작한다).

## 메인 인트로 → 홈 화면 (2026-10-10 사용자 지시)

첫 방문에는 인트로가 돌고, 끝나면 **같은 페이지(`/`)**에서 홈 화면이 나타난다(다른 페이지로 이동하지 않는다). 문구와 별은 **한 시간표**(`src/scripts/intro-timeline.ts`)로 움직이고, 시계·상태 전환은 `src/scripts/home-intro.ts`가 맡는다.

| 시각 | 일어나는 일 |
|------|-------------|
| 0s | 별이 나타난다 |
| 2s | 메인 문장이 나타나 천천히 커지기 시작한다(1배에서 시작) |
| 3.8s | 메인 문장이 나타나고 1.8초 뒤, 작은 문장이 나타나 같이 커진다 |
| 6.0s | 작은 문장이 다 나타나고(0.9초) 1.3초가 지나면, 별들의 중심을 향한 마지막 확대(블랙홀)가 시작된다(약 1.19배에서 이어서) |
| 6.0~10.0s | 4초 동안 확대. 앞쪽은 거의 정지에 가깝다가 **확대 비율이 진행의 4제곱으로 폭발**해 마지막 2초는 블랙홀에 빨려 들어가듯 쏟아진다(약 1.19배 → 300배). 별은 선(꼬리)으로 길게 늘어나며 중심을 축으로 휘감겨 돈다. 문구는 크기를 기준으로 사라진다 |
| 7.7~9.8s | 블랙홀의 **어둠이 가운데에서 번져** 별과 문구를 삼키고 화면 전체가 어두워진다(`--hole`, 색 `--void`) |
| 10.0~11.4s | 어두운 화면에서 흰 바탕(`.paper`)과 요약정리가 1.4초(`--duration-reveal`) 동안 천천히 나타나 0.9배에서 제 크기로 자리 잡는다. 별은 어둠이 덮은 뒤 꺼진다. 헤더·푸터는 절반쯤에 흰 세계 색으로 바뀐다 |

- **확대 속도 → 별의 속도:** 문구가 로그 척도로 커지는 비율(rate)이 별의 비행 속도를 정한다(`flySpeed = 0.4 + 10 × rate`). 천천히 커질 때는 별도 천천히 다가오고, 마지막 확대에서는 별이 빠르게 쏟아지며 더 크고 밝아진다(가장자리 흐림도 풀린다).
- **글씨 떨림 방지:** 확대가 아주 느려서 글자를 프레임마다 새로 그리면 글자 위치가 픽셀 단위로 어긋나 떨린다. `.hero-inner`에 `will-change: transform`(한 번 그린 면을 GPU가 확대)과 `text-rendering: geometricPrecision`(글자 위치를 픽셀에 맞추지 않음)을 둔다. 그래서 확대 시작 크기는 1배이고 작아지지 않는다. 대신 마지막 확대에서 문구가 아주 커질 때는 부드럽게 번진다(이미 사라지는 중이다).
- **상태:** `<html data-intro="play|done|exit">`. 인라인 스크립트(`index.astro`의 `<head>`)가 첫 페인트 전에 정하고, 끝나면 `home-intro.ts`가 `done`으로 바꾼다. `play`인 동안은 홈 화면·푸터를 감추고(`--home-p`로 나타남 조절) 스크롤을 막는다. 값이 없으면(인트로를 안 하는 경우) 홈 화면이 바로 보인다. `exit`는 아래 "흰 세계에서 Knowledge로 나가기"가 쓴다.
- **시계는 실제 시간을 따른다.** 느린 기기에서 프레임이 줄어도 타이밍은 같다. 탭이 숨겨지면 멈춘다. 스크립트가 8초 안에 시작하지 않으면 홈 화면을 보여준다.
- **건너뛰기:** 화면을 누르거나 Enter·Space·Esc를 한 번 누르면 시계가 6배로 빨라져 같은 장면이 짧게 흘러가고(별·확대·흰 세계가 끊기지 않고 끝까지 간다), 이미 빨리 감는 중이거나 마지막 확대(10초)가 끝난 뒤에 누르면 곧바로 홈 화면이 된다.
- **인트로 중에 탭을 눌러 다른 페이지로 가면** 효과 없이 평범한 페이지 전환(크로스페이드)으로 이동한다(`home-exit.ts`는 `data-intro="play"`인 동안 아무것도 하지 않는다).
- **인트로를 하는 경우 (2026-10-11 사용자 승인으로 변경):** 브라우저 세션(탭)에서 처음 들어왔을 때만 한다(`sessionStorage` `intro-seen`). 사이트 안에서 이름·허브로 홈에 돌아오거나 새로고침하면 인트로 없이 홈 화면이 바로 보인다. `prefers-reduced-motion: reduce`도 생략. 보기 싫으면 누르거나 Enter·Space·Esc로 건너뛴다. (홈에 별이 안 보인다는 지적으로 한때 "매번 재생"으로 바꿨으나, 반복이 부담스럽다는 이유로 다시 첫 진입만으로 되돌렸다.)
- 곡선(시각·배율)은 `intro-timeline.ts` 위쪽 상수.

### 홈 화면 구성 (인트로 뒤)

위에서 아래로: **프로필**(사진 + 이름 + 한 줄 소개 + 짧은 설명) → **Now**(`data/now.yaml`) → **Projects**(status가 active인 것, 최대 3개, featured 먼저) → **Recent**(writing + knowledge 최신순 5개). 카드가 아니라 행이고, 데이터가 없는 섹션은 그리지 않는다.
- 한 줄 소개는 About의 `lead`, 짧은 설명은 `site.ts`의 `profile.summary`.
- 사진은 사용자가 `public/images/profile.(jpg|jpeg|png|webp)`로 직접 올린 경우에만 보인다(`src/lib/profile.ts`). 4:5 세로, 120×150px, 얇은 선만 두른다.
- 코드: `src/components/home/{HomeProfile,HomeNow,HomeList}.astro`, 조회는 `src/lib/content.ts`의 `getNow`·`getActiveProjects`·`getRecentPosts`.

## 흰 세계 (2026-10-11 사용자 지시)

사이트는 어두운 세계가 기본이고, **홈의 요약정리와 projects(목록·상세)만 흰 바탕**이다. 인트로의 끝은 블랙홀의 어둠 뒤에 흰 바탕이 천천히 나타나는 방식이고, 홈에서 Knowledge로 갈 때는 흰 빛이 걷히며 별 세계가 드러난다. (처음 구현한 "원이 커지고 줄어드는" 방식은 사용자 지시로 폐기했다.)

- **켜는 법:** `<html data-world="light">`(`BaseLayout`의 `world="light"`; projects 두 페이지와 홈이 넘긴다)가 `tokens.css`의 `[data-world='light']` 블록으로 바탕·글자·선·포인트 색을 바꾼다. 흰 바탕은 순백(`--paper: #fff`). 대비(바탕 #fff 기준): text 17.2, text-muted 5.9, accent 6.2. 탭 바 알약은 흰 바탕 위에서도 글자가 읽히도록 더 진한 유리(`--nav-pill-bg` 0.82)이고 코드 블록은 어느 세계에서나 어둡다(`--pre-bg`).
- **흰 빛(`src/scripts/veil.ts`, Knowledge 도착에서만 쓴다):** 느리게 흐르는 3겹 노이즈가 문턱(level 0~1)을 넘는 곳이 하얘진다. 가장자리는 부드럽게 풀리고(어두운 별 위에서 탁한 회색 띠가 되지 않을 만큼만), 화면 가운데가 먼저 열린다(도착). 6px 칸의 2D 캔버스를 CSS로 늘려 그리므로 WebGL이 필요 없다.
- **인트로 입장:** 위 표(7.7~11.4초). `hole` 곡선은 smoothstep(마지막 확대 진행 0.45→0.95), `home`은 T_END부터 1.4초.
- **홈 → Knowledge, 두 막** (`home-exit.ts` + `topic-stage.ts`, 곡선 `exitFrame`·`arriveFrame`):
  1. 홈(0.55초): 인트로를 마친 흰 홈에서 `/knowledge/` 링크를 일반 왼쪽 클릭하면 요약정리가 흰 바탕 위에서 가운데로 가라앉으며(0.9배, 투명) 사라지고 이동한다.
  2. 도착(약 2.85초): Knowledge가 흰 화면으로 시작해 머무름 없이 곧바로(처음부터 열리도록 직선 35%를 섞은 곡선) 2.85초 동안 흰 빛이 가운데부터 구름처럼 걷힌다. 별은 줄로 늘어난 빠른 비행(+9)에서 평소 속도(0.35)로 잦아들고, 걷힘의 45% 지점에서 태그가 피어난다. 이름(J)은 흰 빛 위에서 어두운 색으로 시작해 절반 걷히면 원래 색이 된다.
  - 효과가 도착한 쪽에서 돌기 때문에 이동을 기다리는 시간이 길지 않고, 마지막 장면이 Knowledge의 별 장면 자체라 홈과 Knowledge의 별 모양이 달라 끊기던 문제가 없다.
- **조건:** 홈이 인트로를 마친 흰 세계 상태에서, 같은 출처의 `/knowledge/` 링크를 일반 왼쪽 클릭(수정 키 없음)으로 눌렀을 때만 쓴다. 인트로가 도는 중이거나 움직임 줄이기이면 효과 없이 평범한 페이지 전환(크로스페이드)이다. `about`·`writing`·`projects`로 갈 때, projects에서 다른 곳으로 갈 때도 평범한 크로스페이드다(넓히려면 `EXIT_TO`에 경로를 더하고 도착 페이지에 같은 head 스크립트·veil 층이 있어야 한다).
- **안전장치:** 효과 도중 뒤로 가기(bfcache) 복귀 시 `pageshow`에서 홈을 되돌리고, 이동이 막히면 `EXIT_SECONDS+1.5`초 뒤 강제 이동한다. `world-exit` 표시는 도착 페이지가 읽는 즉시 지우고 12초가 지난 것은 무시한다(새로고침·다른 경로 진입에서 재생되지 않는다).
- **못 한 것·미확인:** Knowledge → 홈 역방향 효과(지금은 평범한 크로스페이드로 흰 홈이 나타난다), 실제 GPU·실기기의 부드러움(검증은 소프트웨어 GL에서만 했다).
